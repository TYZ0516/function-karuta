# 函數歌牌

看函數，搶下對應的圖形牌。給學習扶助班、原民班用的手機遊戲。

| 模式 | 需要網路 | 說明 |
|---|---|---|
| 單人挑戰電腦 | 不用 | 電腦有烏龜／兔子／獵豹三種速度；二次一般式的電腦時間 ×2 |
| 同機雙人 | 不用 | 手機平放，上下各一半，兩人面對面搶 |
| 線上 1 對 1 | 要 | 一人開房、拿到 4 位數代碼，對手輸入代碼加入 |
| 全班搶牌 | 要 | 老師投影開房，學生掃 QR code 或輸入代碼加入，即時排行榜 |

操作：**輕點牌＝搶牌，長按牌＝放大看清楚**（放開不算搶）。

- 線上版：<https://tyz0516.github.io/function-karuta/>
- 給老師的使用說明：<https://tyz0516.github.io/function-karuta/guide.html>

> **外校老師請注意**：上面的線上版用的是 Firebase 免費方案，整個網站同時最多 100 個連線，所有老師共用。如果要經常在課堂上使用全班搶牌，請照下面的步驟**自己架一份**（免費，約 20 分鐘）。可以直接按右上角「Fork」複製這個 repository，或下載 ZIP。

---

## 一、設定 Firebase（約 10 分鐘，只要做一次）

1. 到 <https://console.firebase.google.com> →「新增專案」，名稱隨意（例如 `function-karuta`）。Google Analytics 可以關掉。
2. **開啟匿名登入**：左側「建構 → Authentication」→「開始使用」→「登入方式」分頁 → 選「匿名」→ 啟用 → 儲存。
3. **建立即時資料庫**：左側「建構 → Realtime Database」→「建立資料庫」
   - 位置選 **asia-southeast1（新加坡）**，離台灣最近。
   - 選「以鎖定模式啟動」。
4. **貼上安全規則**：在 Realtime Database 的「規則」分頁，把整段內容換成 `database.rules.json` 的內容 →「發布」。
5. **取得設定碼**：左上齒輪「專案設定」→「一般」→ 最下面「你的應用程式」→ 點 `</>`（網頁）→ 取個暱稱 → 註冊。
   畫面會出現一段 `const firebaseConfig = { ... }`，把大括號裡的內容貼進 `config.js`，取代原本的空白欄位。
   **請確認裡面有 `databaseURL`**；如果沒有，到 Realtime Database 頁面最上方複製網址（`https://xxx.asia-southeast1.firebasedatabase.app`）自己補上。

> `apiKey` 放在公開網頁上是正常的，Firebase 的網頁應用程式都是這樣。真正保護資料的是第 4 步的安全規則：只有房主能改分數、出題，每個學生只能寫自己的搶牌紀錄，而且每題只能寫一次。

## 二、放上 GitHub Pages

1. 在 GitHub 建立一個新的 **Public** repository（例如 `function-karuta`）。
2. 「Add file → Upload files」，把這個資料夾裡的**所有檔案**拖進去 → Commit。
3. 「Settings → Pages」→ Source 選「Deploy from a branch」→ Branch 選 `main`、資料夾 `/ (root)` → Save。
4. 等 1～3 分鐘，網址會是 `https://你的帳號.github.io/function-karuta/`。
5. 回 Firebase：「Authentication → 設定 → 授權網域」→ 新增 `你的帳號.github.io`。

## 三、上課前測試

- 用兩支手機打開網址，一支開「線上 1 對 1」，另一支「加入房間」，確認能對戰。
- **請在教室用學校 Wi-Fi 測一次**，有些校園網路會擋 Firebase；被擋的話可以改用手機熱點。
- 學生可以用瀏覽器的「加到主畫面」，之後打開就是全螢幕，像 App 一樣。

## 四、全班搶牌上課流程

1. 電腦接投影，打開網址 → 選關卡 →「全班搶牌」。需要的話，可以先打開「作答時間寬鬆 ×1.5」。
2. 投影幕出現房間代碼和 QR code，學生掃描、輸入暱稱加入（請提醒學生**不要輸入真實全名**）。
3. 按「開始」。每題的作答時間：一次 20 秒、二次標準式 30 秒、**二次一般式 60 秒（要配方）**、三次基本 30 秒、三次魔王 45 秒。題目進行中可以按「＋15 秒」（或鍵盤 + 鍵）加時，避免學生因為時間快到而亂猜；計分仍以原本的時間為準。
4. 每人每題只能搶一次。答對的人依速度拿 500～1000 分，全班最快答對的再加 100 分。
5. 公布答案時，投影幕會顯示每張牌各有幾個人選，以及最多人錯選的那張錯在哪裡，可以當場講解。
6. 最後顯示前三名、完整排名，以及**全班最常判斷錯的地方**。
7. 按「關閉房間」會刪掉這個房間的資料。

暱稱最多 8 個字。如果有學生取了不當暱稱，在投影幕的名單或排行榜上**點他的名字**，會跳出選單：
- ✏️ **請改名**：學生手機跳到改名畫面，換一個不同的名字就回到房間，分數保留。
- 🚫 **移出**：這個房間他就不能再加入（以同一支手機的同一個瀏覽器為準）。

## 五、本機測試模式（不用 Firebase）

網址後面加 `?mock=1`，用同一台電腦、同一個瀏覽器開好幾個分頁，就能模擬多人連線（例如一個分頁當老師、三個分頁當學生）。只能在同一台電腦上用。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html` | 網頁本體 |
| `style.css` | 外觀 |
| `levels.js` | 五個關卡的出題、干擾牌、牌面繪製 |
| `app.js` | 各種模式的遊戲流程 |
| `net.js` | 連線（Firebase／本機測試） |
| `config.js` | **要填** Firebase 設定（自架時換成你自己的） |
| `guide.html` | 給老師的使用說明頁 |
| `LICENSE` | 授權條款 |
| `database.rules.json` | 貼到 Firebase 的安全規則 |
| `manifest.json`、`icon-*.png` | 讓手機可以「加到主畫面」 |

## 用量

Firebase 免費方案（Spark）同時連線上限是 100，一班 30～40 人沒有問題。正常關閉的房間會自動刪掉；如果有沒關到的舊房間，可以到 Realtime Database 的「資料」分頁，手動刪除 `rooms` 底下的項目。
